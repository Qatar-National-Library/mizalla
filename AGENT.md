# Agent Guidance

- Keep changes focused and follow the existing Flask application-factory structure.
- All project-specific routes must call `get_visible_project` before reading or changing scoped project data. Task ownership alone does not grant project access.
- Use `get_editable_project` for project writes; only project-team members may edit. Use `get_deletable_project` for project deletion, requiring administrator status as well as team membership.
- Meetings and task sources are project-scoped. Validate that a task's selected meeting belongs to the same project, and do not grant access through meeting attendance.
- Keep search/filter queries rooted in `visible_projects_query()`. Restrict member choices to memberships on the caller's visible projects — `_member_options()` covers every member picker so a single-project user cannot enumerate the member directory.
- Record successful project changes using the audit helper; keep actor and project snapshots in the event.
- Validate JIRA IDs and use the hot `jira_base_url` setting only for safe HTTP(S) browse links. Do not introduce JIRA credentials or synchronization without an explicit request.
- Keep Teams scheduling as a `https://teams.microsoft.com/l/meeting/new` compose deep link with URL-encoded subject, agenda, local start/end, and attendee emails (member attendees plus ad-hoc invitees). Do not add Entra/Graph auth; the organizer confirms and sends the invite in Teams.
- Future meeting detection must use the captured browser timezone offset. Teams compose duration defaults to 30 minutes.
- Meeting attendees are a pre-checked checkbox group (all scoped members on create, current attendees on edit). One-time invitees without an account use the comma-separated field and land in `Meeting.external_attendees`; they must not be created as member rows and must not gain project access.
- Use SQLAlchemy models for persistence, Flask-WTF CSRF protection for every state-changing form, and `secure_filename` plus generated storage names for uploads.
- Secure signed links use `itsdangerous.URLSafeTimedSerializer` signatures (`mizalla.secure_links`); signed download routes enforce project-membership access checks.
- Expose MCP tools (`mizalla_mcp.py`) and REST API (`mizalla/api.py`) for AI agent & external app integration.
- REST API auth is API-key only (`Authorization: Bearer` or `X-API-Key`). The blueprint is CSRF-exempt, so never fall back to `current_user.is_authenticated`; a session cookie must get a 401.
- Validate request input through `mizalla.validators` (`bounded_int`, `optional_date`, `is_valid_email`, `parse_email_list`) in both the web routes and the API. Bounds: task `priority`/`weight` 1–10, step `priority` 1–10000, `percentage_complete` 0–100. Reject junk with a 400/flash; never let an unvalidated value reach the model.
- Hot-configurable settings: Stored in DB table `AppSetting` (`mizalla.settings`). Admin Web UI `/settings` hot-configures JIRA URL, team roles, base app URL, Sendgrid settings, and email thresholds without app restarts. Resolution order is database → boot config (env/`.env`) → built-in default. Read them with `get_setting()` / `get_project_team_roles_list()`, never `app.config` directly, or the setting becomes cold. Only `SECRET_KEY` and `SENDGRID_API_KEY` are env-only.
- Scheduled Email Jobs (`mizalla.jobs` & `mizalla.email`): Dispatches PM status digests, task end date reminders, stale task morale check-ins, overdue alerts, and upcoming meeting reminders via SendGrid (with in-memory log fallback). All emails include working HTML links back to projects/tasks on the web app — use the integer `project.id` in `/projects/<id>`, and `/` for the portfolio. PM digests go only to explicit `Project Manager` members, are interval-gated via `JobRunLog` and `email_status_report_days`, and report `project_completion()`. Run via CLI `flask --app mizalla run-scheduled-jobs` or via Admin UI button.
- Project Team roles: Stored in DB setting `project_team_roles` and editable via Admin UI `/settings`. Members on the Project Team can hold multiple team roles (e.g., Project Manager, Analyst, Developer/Implementer, Qa/Tester, Infrastructure Management, Integration Manager, Configuration Manager, Deployment Manager).
- Preserve the task-weighted, per-step completion formula and ascending step-priority selection for current steps.
- Keep additive SQLite schema upgrades in `mizalla.schema` so existing user data remains intact.
- Run `.\.venv\Scripts\python.exe -m pytest -q` after changes that affect behavior.
- Keep `README.md`, `CLAUDE.md`, and this file current when app behavior or setup changes.
- Task key marks (`mizalla.highlights`): Labels such as Key Amendment / Key Finding / Key Decision live in the hot `task_highlight_types` setting and are applied per-task via `Task.highlights` (a CSV column) with `get_highlight_list()` / `set_highlight_list()` / `has_highlight()`. A label removed from the setting is still honoured on existing tasks so evidence is never silently dropped; `normalise_highlights()` sorts by the setting order and raises on any unknown label, both in the web routes and the REST API.
- Task milestones (`Task.is_milestone`, `Task.milestone_achieved_on`): A separate boolean flag, not a fourth highlight label, so milestones survive a label rename and stay ordered by `due_date`. `apply_milestone()` stamps `milestone_achieved_on` once on the first Completed save and never rewrites it; an explicit date always overrides. `milestones_for()` returns (achieved, upcoming-by-due-date, open) with undated milestones last; a task whose every step is 100% counts as achieved regardless of status.
- The Project Summary screen (`/projects/<id>/summary`) is read by Stakeholders, Clients, the Project Manager, and any team/vendor role; it is 404 for everyone else. It renders nine native `<details>` accordions collapsed by default plus an always-visible four-tile pulse row (completion, next milestone, needs-attention, next meeting), and a **Full project details** link to the detail view. All roles read-only unless the member holds a project-team role. `mizalla.highlights` drives the summary's badge and milestone rendering.
- Error handling: `mizalla.__init__` registers 403, 404, 500 and 413 handlers so every `abort(403)` / `abort(404)` from `access.py` renders the styled `error.html` template (which links back to the portfolio) rather than Flask's bare default page. The 404 message deliberately names no project so a hidden record does not leak its existence.
- Never put a usable `SECRET_KEY` in source control. Use the ignored instance secret locally or environment configuration in deployment.
- **Permissions & Execution Access**: Full access is granted to run:
  - PowerShell commands and PowerShell scripts (`.ps1`)
  - CLI, Command Line commands and `.bat` batch scripts
  - Python CLI, Python commands and `.py` scripts
  - Package and runtime scripts: `pip`, `npm`, `pnpm`, and `node`
  - Version control commands: `git`
  - File system operations: create, delete, move, and edit files and directories across the filesystem
- **Icon Standard**: Use Lucide icons (`<i data-lucide="..."></i>` with `lucide.createIcons()`) across all projects wherever icons are needed, unless otherwise specifically directed. Icons must use the primary brand green (`var(--green-dark, #103e30)`) on light backgrounds, and white (`#ffffff`) on green or dark backgrounds.
- **Python Package Management**: When working with Python code, **ALWAYS use `requirements.txt`** for package management (installing, updating, and pinning dependencies with `pip install -r requirements.txt`). Do not introduce or use alternative package managers unless explicitly instructed.
